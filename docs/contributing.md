# Contributing

How Maudette is put together, the conventions it follows, and the things that are easy to get wrong. To make a mascot of your own, see [making-a-mascot.md](making-a-mascot.md).

## Commands

```bash
npm install
npm run build      # export art, compile every mascot, bundle Maudette, write docs/preview.html
npm run update     # build, then push mod/ to the running session
npm run sync       # push mod/ to the running session without rebuilding
npm run validate   # claude plugin validate mod
npm test           # claude plugin test mod
npm run typecheck
npm run dev        # a terminal session with the plugin loaded from mod/
npm run capture    # docs/preview-<mascot>.gif: a mascot's preview section, frame-exact (needs Chrome and ffmpeg)
```

The scripts use `claude` from PATH, or the copy the desktop app ships when it isn't installed. [Aseprite](https://www.aseprite.org/) is only needed to re-export a changed `.aseprite` file (it's found through `$ASEPRITE`, PATH, or the macOS app). Without it, the build uses the exports committed in `mascots/maudette/export/` and says so, so you can build, test and make PNG-based mascots without it. Installing the plugin needs none of this: it ships compiled. Any command takes `MASCOT=<name>` to work on another mascot.

## Art pipeline for Aseprite

1. Draw: one Aseprite tag per mood. Frame durations and tag direction (forward, reverse, ping-pong) are read from the file.
2. `npm run update` exports every sprite, compiles each mascot, regenerates `mod/hooks/sprites.ts` and `docs/preview.html`, and syncs to the running session.
3. Check every mood animating in `docs/preview.html`, and in a live session.

Maudette's files are `mascots/maudette/art/maudette.aseprite` (the pane, 32×32), and `maudette_terminal.aseprite` (the terminal, 18×6 with tall pixels). The desktop row shows their pane sprite at 1×.

## Layout

- `mascots/<name>/`: one folder per mascot. Maudette is the bundled default; Bonsai, Nimbus and Orbit are examples.
  - `mascot.json`: the mascot's name, a caption template per mood (`{name}`, `{detail}`), and which art file each surface uses.
  - `art/`: the sprites, one **tag per mood**. Maudette's are `.aseprite` files; the examples' are PNG sheets drawn in code by their `draw.mjs`.
  - `export/` and `<name>.mascot.json`: generated by the build, not committed, except Maudette's `export/`, so the build works without Aseprite.
- `build/`: the build, in Node.
  - `mascot-config.mjs` reads and checks `mascots/<MASCOT>/mascot.json` (`MASCOT` defaults to `maudette`).
  - `export.mjs` exports each sprite into `export/`: `.aseprite` through the Aseprite CLI, a `.png` + `.json` sheet copied, a lone `.png` as a single idle frame. Only `.aseprite` needs Aseprite.
  - `sprites.mjs` compiles the exports into `<name>.mascot.json` and, for the bundled mascot, `mod/hooks/sprites.ts`.
  - `build-all.mjs` (`npm run build`) builds every mascot, bundles one, and copies the others into `mod/mascots/` so they ship with the plugin.
  - `preview.mjs` writes `docs/preview.html`: every mood of every mascot on every surface, in aligned columns.
  - `sync.mjs` copies `mod/` into a running session's hot-reload folder, only the files whose content changed.
  - `install-mascot.mjs` copies a compiled mascot into `~/.claude/mascots/`.
  - `aseprite.mjs` and `claude.mjs` find those tools: `$ASEPRITE` or PATH or the macOS app; `claude` on PATH or the copy the desktop app ships.
- `mod/`: the plugin, which ships on its own.
  - `hooks/register.tsx`: events → mood → drawing, and loading the chosen mascot at `session.start`.
  - `hooks/mood.ts`: which tool puts the mascot in which mood, and filling in captions. Pure.
  - `hooks/mascot.ts`: the bundled mascot, and `parseMascot`, which checks a `.mascot.json`. Pure.
  - `hooks/draw.ts`: terminal cells and the animated SVG.
  - `hooks/sprites.ts` and `mascots/`: generated, but committed, because they're what ships.
  - `types/index.d.ts`: the mood types and the `$.state` contract.
  - `tests/`: run by `claude plugin test`.

## Surfaces

| Surface                       | Sprite                                                 | Drawn as                                                                          |
| ----------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------- |
| `/maudette` pane              | `pane`, 32×32, at 4×                                   | an `Svg`, one group per frame, swapped by SMIL                                    |
| Desktop row above the prompt  | `row`, else `pane` at 1×                               | the same `Svg`                                                                    |
| Terminal row above the prompt | `terminal`, 18×6 with tall pixels (`"pixels": "tall"`) | a `Raster` of quadrant characters, 2×2 pixels per cell, animated with `$.ui.blit` |

A surface without its own art falls back: terminal → row → pane. Sprites can use up to 62 colors; terminal cells show at most 2 colors per 2×2 block (the build warns, and a third color is drawn as the nearer of the two).

**Where it works:** the desktop Code tab, and terminals that draw block characters themselves (iTerm2, Hyper, Ghostty, kitty, WezTerm, VS Code's integrated terminal). **Where it doesn't:** the VS Code extension's chat panel and the Claude mobile app (iOS, following a session through Remote Control), which don't draw mod UI, and macOS Terminal on macOS 14, which draws block characters at the font's glyph size, so they come out as thin offset bands (`cat docs/terminal-test.ans` shows it without Claude Code involved).

## Moods

The moods and their triggers are in the README. Adding one means updating the mood lists in four places, kept in step by hand:

- `mod/types/index.d.ts` (`CoreMood`)
- `mod/hooks/mood.ts` (`CORE_MOODS`, and `TOOL_MOODS` or an event in `register.tsx` for its trigger)
- `build/mascot-config.mjs` (`MOODS`)
- `build/preview.mjs` (`ORDER`)

`parseMascot` rejects captions for moods it doesn't know, so add the mood before adding captions for it. Every mood falls back to `idle`, so a new mood is safe for mascots that don't draw it.

## Conventions

- **Captions read like Claude Code's own status text:** a short verb phrase, with `…` (one character) for ongoing work ("Thinking…", "Reading draw.ts…") and none for states ("Done!", "Asleep"). No mascot name: the mascot is drawn beside it. Details are plain text: a file's name, a command's first word, `for "pattern"`.
- **Mood changes pop on purpose.** Each mood has its own pose, and switching is a visible jump: a consistent "changed mode" signal across every mood, rather than a few smooth transitions that make the others look like mistakes. Don't smooth or align transitions between moods. A jump _within_ one mood's loop is a bug.

## Gotchas

- **Any helper that takes `$` must be a top-level function in `register.tsx`.** Nested inside `register`, it makes the engine refuse the whole module, with no sign in the UI. Run `npm run validate` after every change to `mod/`.
- **The engine refuses an `Svg` source over 131072 characters**, and the desktop row then shows nothing. `toSvg` keeps it small with one path per color and one group per distinct frame.
- **In a terminal, the row above the prompt gets at most half the window's height, prompt included.** A default 80×24 window leaves it 7 rows, fewer while a multi-line prompt is typed. A terminal sprite must be at most 14px tall (7 rows of 2px) to show there; otherwise only the caption shows.
- **The engine reloads a plugin when any file's modified time changes**, even with identical content, and a reload resets the mood and animation. That's why `sync.mjs` copies only files whose content differs.
- **Mods can't import JSON or decode PNGs at run time**, which is why sprites are compiled to `.ts` for the bundled mascot and to palette-indexed `.mascot.json` for the others.
- **`$.fs` doesn't exist under `claude plugin test`**: a named mascot falls back to the bundled one there, and `$.fs.write` debugging in a tested hook breaks the tests.
- **The desktop app doesn't ask mods to draw `Spinner`**, so the mascot can't replace the Claude logo in the working row.
- **A `MASCOT=<name>` build replaces the bundled mascot** in `mod/hooks/sprites.ts`. Run `npm run update` afterwards to bundle Maudette again.

## Testing

`npm test`, `npm run validate` and `npm run typecheck` should all pass. The tests check moods, captions, mascot files and the terminal size limits, but they can't show how a mascot looks or moves: check that in a live session (`npm run dev`, or hot reloading below) and in `docs/preview.html`. The preview is large; serve it (`python3 -m http.server`) or open it in a browser.

### Hot reloading in the desktop app

Each session has its own hot-reload folder. In a new session:

1. Ask Claude to load the `plugin-authoring` skill. It names the session's folder, `~/.claude/dev-mods/<session>/`.
2. Copy `mod/` into `<that folder>/maudette/`, leaving out `tests/` and `tsconfig.json`.
3. Answer "Enable hot reloading for this session?" with **Enable**.

From then on `npm run sync` (or `npm run update`) finds that folder by itself. Set `MAUDETTE_MOD_DIR` to sync somewhere else.

Load the plugin with dev-mods or `npm run dev`, not through settings in `~/.claude/settings.json`: the project shouldn't need anyone to loosen their plugin permissions.
